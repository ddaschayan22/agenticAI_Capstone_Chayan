# Goal 1: Build a single agentic payments operations solution

## Task 1.1: Ingest and normalize payment operations events

**Tools required:**

### Payment processor, bank, and payment-rail APIs

**Tool description:** Connects to card, UPI, ACH, wire, bank, and processor systems to retrieve payment statuses, responses, authorization details, refunds, disputes, and settlement information, and execute authorized payment actions.

**Parameters:**

```json
{
  "transaction_ids": ["TXN-10001"],
  "authorization_references": ["AUTH-45678"],
  "payment_rail": "UPI",
  "date_range": {
    "start": "2026-08-24T00:00:00Z",
    "end": "2026-08-24T23:59:59Z"
  },
  "amount": 2500.00,
  "merchant_id": "MER-1001",
  "dispute_id": null,
  "refund_id": null,
  "action_request": null
}
```

### Transaction ledger and payment-event datastore

**Tool description:** Provides the authoritative internal financial and event history for payment attempts, postings, reversals, refunds, and adjustments.

**Parameters:**

```json
{
  "transaction_ids": ["TXN-10001"],
  "account_ids": ["ACC-10001"],
  "merchant_ids": ["MER-1001"],

    "start": "2026-08-24T00:00:00Z",
    "end": "2026-08-24T23:59:59Z"
  }
}
```

**Outcome:**

```json
{
  "result": "success",
  "events_ingested": 1250,
  "payment_rails": ["CARD", "UPI", "ACH", "WIRE"],
  "normalized_events": 1242,
  "normalization_errors": 8,
  "common_case_fields": [
    "transaction_id",

}
```

## Standard format to use for the remaining tasks

For consistency, every task should follow exactly this structure:

````text
## Task X.X: <Task name>

**Tools required:**

### <Tool Name>

**Tool description:** <The tool's one fixed/canonical description.>

**Parameters:**

```json
{
  "<fixed parameter 1>": "<value>",
  "<fixed parameter 2>": "<value>"
}
````

### <Another Tool Name>

**Tool description:** <The same canonical description used everywhere else for this tool.>

**Parameters:**

```json
{
  "<fixed parameter 1>": "<value>",
  "<fixed parameter 2>": "<value>"
}
```

**Outcome:**

```json
{
  "result": "success",
  "<task-specific result key>": "<result value>",
  "<additional result key>": "<result value>"
}
```

```

### Key rule

**Tool description and parameter schema are properties of the tool, not of the task.** Therefore:

- The **Payment processor** tool always has the same description and the same 9 parameters.
- The **Ledger** tool always has the same description and the same 8 parameters.
- The **Policy engine** always has the same description and the same 10 parameters.
- Only the **values** of those parameters change from task to task.
- The **Outcome JSON** can vary by task because it represents the result of that particular operation.
- When one tool invokes another tool, the second tool receives its **own predefined parameter schema**, rather than inheriting or redefining parameters from the calling tool.
```
